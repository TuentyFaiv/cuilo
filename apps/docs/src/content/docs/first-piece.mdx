In this tutorial you add a `status-badge` atom from the official `ui` pack to a SvelteKit project. Then you edit it and see what cuilo records about it, and you undo the change. You need cuilo on your `PATH`; see [Install](/install/). You also need Node.js to create the project.

## Set up a project

Use a SvelteKit project with TypeScript that you already have, or create one with the Svelte CLI.

<Steps>

1. Create the project and go into it. The Svelte CLI installs its dependencies with npm:

   ```sh
   npx sv create my-app --template minimal --types ts --no-add-ons --install npm
   cd my-app
   ```

2. Check what cuilo detects:

   ```sh
   cuilo detect
   ```

   ```text
   {
     "stack": {
       "framework": [
         "svelte",
         "sveltekit"
       ],
       "language": [
         "typescript"
       ],
       "runtime": [
         "node"
       ],
       "package_manager": [
         "npm"
       ],
       "import_style": [
         "imports-ts"
       ]
     },
     "env": []
   }
   ```

</Steps>

The `ui` pack's Svelte variant needs both `svelte` and TypeScript. Without `typescript` in `package.json` or a `tsconfig.json`, cuilo reports that no variant matches. See [Stack detection](/guides/stack-detection/).

## Preview the plan

Ask for the plan without writing anything:

```sh
cuilo add ui/atom status-badge --dry-run
```

```text
add ui/atom
  create  src/ui/atoms/status-badge/status-badge.svelte
  create  src/ui/atoms/status-badge/index.ts
```

Here is how to read it:

- `ui/atom` is the pack and the piece. `status-badge` is the piece's `name` input. You can also write it as `StatusBadge`.
- The files go to `src/ui/atoms/`, the piece's default folder.
- The component keeps its styles in a `<style>` block because the project does not use Tailwind. With Tailwind, it gets utility classes instead.
- The plan has no test file because the project has no Vitest. Add `-i tests=true` to get one. The plan then also lists the test packages to add.

## Apply it

Run the same command without `--dry-run`. cuilo shows the plan again and asks before writing:

```sh
cuilo add ui/atom status-badge
```

```text
add ui/atom
  create  src/ui/atoms/status-badge/status-badge.svelte
  create  src/ui/atoms/status-badge/index.ts
Apply these changes? [y/N] y
Applied transaction 1 (2 file(s)). Undo it with `cuilo undo`.
```

The component is ordinary Svelte code, and you can edit it:

```svelte title="src/ui/atoms/status-badge/status-badge.svelte"
<script lang="ts" module>
	export type StatusBadgeTone = "neutral" | "accent";
</script>

<script lang="ts">
	import type { HTMLAttributes } from "svelte/elements";

	interface Props extends HTMLAttributes<HTMLSpanElement> {
		/** Visual emphasis. */
		tone?: StatusBadgeTone;
	}

	let { tone = "neutral", class: className, children, ...rest }: Props = $props();

	const classes = { root: "root" };
</script>

<span {...rest} class={[classes.root, className]} data-tone={tone}>
	{@render children?.()}
</span>

<style>
	.root {
		display: inline-flex;
		align-items: center;
		gap: 0.25rem;
		padding: 0.125rem 0.5rem;
		border-radius: 999px;
		font-size: 0.75rem;
		font-weight: 600;
		line-height: 1.5;
		color: var(--ui-neutral-foreground, #3f3f46);
		background: var(--ui-neutral, #f4f4f5);
	}

	.root[data-tone="accent"] {
		color: var(--ui-accent-foreground, #ffffff);
		background: var(--ui-accent, #4f46e5);
	}
</style>
```

`index.ts` exports it as `StatusBadge`. The component type-checks with the rest of the project:

```sh
npm run check
```

The last line `svelte-check` prints:

```text
svelte-check found 0 errors and 0 warnings
```

cuilo also created two things next to `package.json`:

- `cuilo.lock`, which you commit. It pins the pack and records the piece:

  ```toml title="cuilo.lock"
  # Generated by cuilo. Commit this file; do not edit it by hand.

  version = 1

  [[pack]]
  name = "ui"
  version = "0.2.0"
  source = "official:ui"
  digest = "sha256:bdc4594e8a21617e1c4bb94cfd651498ff56cc33169bbf9048d40773d80b696e"

  [[instance]]
  id = "atom-d479162786"
  pack = "ui"
  pack_version = "0.2.0"
  piece = "atom"
  variant = "svelte"
  target = "src/ui/atoms"
  ```

  After that come the stack and inputs the piece was generated with, and one `[[instance.file]]` table per file with the hash of what cuilo wrote.

- `.cuilo/`, the local history that `cuilo undo` uses. It ignores itself in Git.

<Aside type="tip">
Without a terminal, for example in a script, cuilo does not ask. It prints the plan, changes nothing and exits with code 2. Pass `--yes` to apply without asking.
</Aside>

## See what cuilo tracks

<Steps>

1. Check the generated files:

   ```sh
   cuilo status
   ```

   ```text
   clean     src/ui/atoms/status-badge/index.ts
   clean     src/ui/atoms/status-badge/status-badge.svelte
   ```

2. Edit line 2 of `status-badge.svelte` to add a tone:

   ```svelte
   export type StatusBadgeTone = "neutral" | "accent" | "success";
   ```

3. Check again. The edited file is now `modified`:

   ```sh
   cuilo status
   ```

   ```text
   clean     src/ui/atoms/status-badge/index.ts
   modified  src/ui/atoms/status-badge/status-badge.svelte
   ```

4. Ask where a line comes from, with `path:line`:

   ```sh
   cuilo why src/ui/atoms/status-badge/status-badge.svelte:2
   cuilo why src/ui/atoms/status-badge/status-badge.svelte:13
   ```

   ```text
   src/ui/atoms/status-badge/status-badge.svelte:2 is yours: added or changed since generation; ui 0.2.0 piece `atom`
   src/ui/atoms/status-badge/status-badge.svelte:13 is from the pack (line 13 of the original); ui 0.2.0 piece `atom`
   ```

</Steps>

This record is what makes updates safe. When the `ui` pack ships a new version, `cuilo update ui` merges it into your edited file instead of overwriting your line. See [Updating packs](/guides/updates/).

## Look back and undo

<Steps>

1. List the transactions you can undo:

   ```sh
   cuilo log
   ```

   ```text
      1  add ui/atom  (2 file(s))
   ```

2. Undo the last one:

   ```sh
   cuilo undo
   ```

   ```text
   error: these files changed after transaction 1; undo with force to discard the edits: src/ui/atoms/status-badge/status-badge.svelte
   ```

   cuilo refuses, because undoing would throw away your edit to line 2.

3. Put line 2 back the way it was and run `cuilo undo` again. Or discard the edit with `--force`:

   ```sh
   cuilo undo --force
   ```

   ```text
   Undid transaction 1: add ui/atom
   ```

4. Check that nothing is left:

   ```sh
   cuilo status
   ```

   ```text
   Nothing generated yet.
   ```

</Steps>

The transaction created `cuilo.lock`, so undoing it removed the lockfile too. Of what cuilo added, only `.cuilo/` remains.
