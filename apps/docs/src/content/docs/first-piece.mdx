In this tutorial you add a `status-badge` atom from the official `ui` pack to a React project. Then you edit it and see what cuilo records about it, and you undo the change. You need cuilo on your `PATH`; see [Install](/install/).

## Set up a project

Use a React and TypeScript project you already have, or make an empty one. Nothing gets installed in this tutorial. cuilo only reads `package.json`.

<Steps>

1. Make a folder and go into it:

   ```sh
   mkdir my-app && cd my-app
   ```

2. Create `package.json`:

   ```json title="package.json"
   {
   	"dependencies": { "react": "19.0.0" },
   	"devDependencies": { "typescript": "6.0.0" }
   }
   ```

3. Check what cuilo detects:

   ```sh
   cuilo detect
   ```

   ```text
   {
     "stack": {
       "framework": [
         "react"
       ],
       "language": [
         "typescript"
       ],
       "runtime": [
         "node"
       ],
       "package_manager": [
         "npm"
       ]
     },
     "env": []
   }
   ```

</Steps>

The `ui` pack's React variant needs both `react` and `typescript`. Without `typescript` in `package.json` or a `tsconfig.json`, cuilo reports that no variant matches. See [Stack detection](/guides/stack-detection/).

## Preview the plan

Ask for the plan without writing anything:

```sh
cuilo add ui/atom status-badge --dry-run
```

```text
add ui/atom
  create  src/ui/atoms/status-badge/status-badge.module.css
  create  src/ui/atoms/status-badge/status-badge.tsx
  create  src/ui/atoms/status-badge/index.ts
```

Here is how to read it:

- `ui/atom` is the pack and the piece. `status-badge` is the piece's `name` input. You can also write it as `StatusBadge`.
- The files go to `src/ui/atoms/`, the piece's default folder.
- The plan has a CSS module because the project does not use Tailwind.
- The plan has no test file because the project has no Vitest. Add `-i tests=true` to get one. The plan then also lists the test packages to add.

## Apply it

Run the same command without `--dry-run`. cuilo shows the plan again and asks before writing:

```sh
cuilo add ui/atom status-badge
```

```text
add ui/atom
  create  src/ui/atoms/status-badge/status-badge.module.css
  create  src/ui/atoms/status-badge/status-badge.tsx
  create  src/ui/atoms/status-badge/index.ts
Apply these changes? [y/N] y
Applied transaction 1 (3 file(s)). Undo it with `cuilo undo`.
```

The component is ordinary code, and you can edit it:

```tsx title="src/ui/atoms/status-badge/status-badge.tsx"
import type { ComponentProps } from "react";

import styles from "./status-badge.module.css";

export type StatusBadgeTone = "neutral" | "accent";

export type StatusBadgeProps = ComponentProps<"span"> & {
	/** Visual emphasis. */
	tone?: StatusBadgeTone;
};

const classes = styles;

/** The smallest UI building block: an inline, label-sized element. */
export function StatusBadge({ tone = "neutral", className, ...props }: StatusBadgeProps) {
	return <span {...props} data-tone={tone} className={[classes.root, className].filter(Boolean).join(" ")} />;
}
```

cuilo also created two things next to `package.json`:

- `cuilo.lock`, which you commit. It pins the pack and records the piece:

  ```toml title="cuilo.lock"
  # Generated by cuilo. Commit this file; do not edit it by hand.

  version = 1

  [[pack]]
  name = "ui"
  version = "0.2.0"
  source = "official:ui"
  digest = "sha256:659daddc6c30ad71639fbda1bee3051eefa532680676fd546cbfaed8fef47cf4"

  [[instance]]
  id = "atom-d479162786"
  pack = "ui"
  pack_version = "0.2.0"
  piece = "atom"
  variant = "react"
  target = "src/ui/atoms"
  ```

  After that come the stack and inputs the piece was generated with, and one `[[instance.file]]` table per file with the hash of what cuilo wrote.

- `.cuilo/`, the local history that `cuilo undo` uses. It ignores itself in Git.

<Aside type="tip">
Without a terminal, for example in a script, cuilo does not ask. It prints the plan, changes nothing and exits with code 2. Pass `--yes` to apply without asking.
</Aside>

## See what cuilo tracks

<Steps>

1. Check the generated files:

   ```sh
   cuilo status
   ```

   ```text
   clean     src/ui/atoms/status-badge/index.ts
   clean     src/ui/atoms/status-badge/status-badge.module.css
   clean     src/ui/atoms/status-badge/status-badge.tsx
   ```

2. Edit line 5 of `status-badge.tsx` to add a tone:

   ```tsx
   export type StatusBadgeTone = "neutral" | "accent" | "success";
   ```

3. Check again. The edited file is now `modified`:

   ```sh
   cuilo status
   ```

   ```text
   clean     src/ui/atoms/status-badge/index.ts
   clean     src/ui/atoms/status-badge/status-badge.module.css
   modified  src/ui/atoms/status-badge/status-badge.tsx
   ```

4. Ask where a line comes from, with `path:line`:

   ```sh
   cuilo why src/ui/atoms/status-badge/status-badge.tsx:5
   cuilo why src/ui/atoms/status-badge/status-badge.tsx:15
   ```

   ```text
   src/ui/atoms/status-badge/status-badge.tsx:5 is yours: added or changed since generation; ui 0.2.0 piece `atom`
   src/ui/atoms/status-badge/status-badge.tsx:15 is from the pack (line 15 of the original); ui 0.2.0 piece `atom`
   ```

</Steps>

This record is what makes updates safe. When the `ui` pack ships a new version, `cuilo update ui` merges it into your edited file instead of overwriting your line. See [Updating packs](/guides/updates/).

## Look back and undo

<Steps>

1. List the transactions you can undo:

   ```sh
   cuilo log
   ```

   ```text
      1  add ui/atom  (3 file(s))
   ```

2. Undo the last one:

   ```sh
   cuilo undo
   ```

   ```text
   error: these files changed after transaction 1; undo with force to discard the edits: src/ui/atoms/status-badge/status-badge.tsx
   ```

   cuilo refuses, because undoing would throw away your edit to line 5.

3. Put line 5 back the way it was and run `cuilo undo` again. Or discard the edit with `--force`:

   ```sh
   cuilo undo --force
   ```

   ```text
   Undid transaction 1: add ui/atom
   ```

4. Check that nothing is left:

   ```sh
   cuilo status
   ```

   ```text
   Nothing generated yet.
   ```

</Steps>

The transaction created `cuilo.lock`, so undoing it removed the lockfile too. Only `package.json` and `.cuilo/` remain.
