En este tutorial agregas un átomo `status-badge` del pack oficial `ui` a un proyecto de SvelteKit. Después lo editas, ves lo que cuilo registra de él y deshaces el cambio. Necesitas cuilo en tu `PATH`; consulta [Instalación](/es-mx/install/). También necesitas Node.js para crear el proyecto.

## Prepara un proyecto

Usa un proyecto de SvelteKit con TypeScript que ya tengas, o crea uno con la CLI de Svelte.

<Steps>

1. Crea el proyecto y entra en él. La CLI de Svelte instala sus dependencias con npm:

   ```sh
   npx sv create my-app --template minimal --types ts --no-add-ons --install npm
   cd my-app
   ```

2. Revisa lo que detecta cuilo:

   ```sh
   cuilo detect
   ```

   ```text
   {
     "stack": {
       "framework": [
         "svelte",
         "sveltekit"
       ],
       "language": [
         "typescript"
       ],
       "runtime": [
         "node"
       ],
       "package_manager": [
         "npm"
       ],
       "import_style": [
         "imports-ts"
       ]
     },
     "env": []
   }
   ```

</Steps>

La variante de Svelte del pack `ui` necesita tanto `svelte` como TypeScript. Sin `typescript` en `package.json` o un `tsconfig.json`, cuilo avisa que ninguna variante coincide. Consulta [Detección del stack](/es-mx/guides/stack-detection/).

## Revisa el plan

Pide el plan sin escribir nada:

```sh
cuilo add ui/atom status-badge --dry-run
```

```text
add ui/atom
  create  src/ui/atoms/status-badge/status-badge.svelte
  create  src/ui/atoms/status-badge/index.ts
```

Así se lee:

- `ui/atom` es el pack y la pieza. `status-badge` es la entrada `name` de la pieza. También puedes escribirlo como `StatusBadge`.
- Los archivos van a `src/ui/atoms/`, la carpeta por defecto de la pieza.
- El componente trae sus estilos en un bloque `<style>` porque el proyecto no usa Tailwind. Con Tailwind, recibe clases de utilidad en su lugar.
- El plan no trae archivo de pruebas porque el proyecto no tiene Vitest. Agrega `-i tests=true` para obtener uno. Entonces el plan también lista los paquetes de pruebas que hay que agregar.

## Aplícalo

Corre el mismo comando sin `--dry-run`. cuilo vuelve a mostrar el plan y pregunta antes de escribir:

```sh
cuilo add ui/atom status-badge
```

```text
add ui/atom
  create  src/ui/atoms/status-badge/status-badge.svelte
  create  src/ui/atoms/status-badge/index.ts
Apply these changes? [y/N] y
Applied transaction 1 (2 file(s)). Undo it with `cuilo undo`.
```

El componente es código de Svelte normal y puedes editarlo:

```svelte title="src/ui/atoms/status-badge/status-badge.svelte"
<script lang="ts" module>
	export type StatusBadgeTone = "neutral" | "accent";
</script>

<script lang="ts">
	import type { HTMLAttributes } from "svelte/elements";

	interface Props extends HTMLAttributes<HTMLSpanElement> {
		/** Visual emphasis. */
		tone?: StatusBadgeTone;
	}

	let { tone = "neutral", class: className, children, ...rest }: Props = $props();

	const classes = { root: "root" };
</script>

<span {...rest} class={[classes.root, className]} data-tone={tone}>
	{@render children?.()}
</span>

<style>
	.root {
		display: inline-flex;
		align-items: center;
		gap: 0.25rem;
		padding: 0.125rem 0.5rem;
		border-radius: 999px;
		font-size: 0.75rem;
		font-weight: 600;
		line-height: 1.5;
		color: var(--ui-neutral-foreground, #3f3f46);
		background: var(--ui-neutral, #f4f4f5);
	}

	.root[data-tone="accent"] {
		color: var(--ui-accent-foreground, #ffffff);
		background: var(--ui-accent, #4f46e5);
	}
</style>
```

`index.ts` lo exporta como `StatusBadge`. El componente pasa la revisión de tipos con el resto del proyecto:

```sh
npm run check
```

La última línea que imprime `svelte-check`:

```text
svelte-check found 0 errors and 0 warnings
```

cuilo también creó dos cosas junto a `package.json`:

- `cuilo.lock`, que va en tus commits. Fija el pack y registra la pieza:

  ```toml title="cuilo.lock"
  # Generated by cuilo. Commit this file; do not edit it by hand.

  version = 1

  [[pack]]
  name = "ui"
  version = "0.2.0"
  source = "official:ui"
  digest = "sha256:bdc4594e8a21617e1c4bb94cfd651498ff56cc33169bbf9048d40773d80b696e"

  [[instance]]
  id = "atom-d479162786"
  pack = "ui"
  pack_version = "0.2.0"
  piece = "atom"
  variant = "svelte"
  target = "src/ui/atoms"
  ```

  Después vienen el stack y las entradas con los que se generó la pieza, y una tabla `[[instance.file]]` por archivo con el hash de lo que escribió cuilo.

- `.cuilo/`, el historial local que usa `cuilo undo`. Se ignora a sí mismo en Git.

<Aside type="tip">
Sin una terminal, por ejemplo en un script, cuilo no pregunta. Imprime el plan, no cambia nada y sale con el código 2. Pasa `--yes` para aplicar sin preguntar.
</Aside>

## Mira lo que cuilo rastrea

<Steps>

1. Revisa los archivos generados:

   ```sh
   cuilo status
   ```

   ```text
   clean     src/ui/atoms/status-badge/index.ts
   clean     src/ui/atoms/status-badge/status-badge.svelte
   ```

2. Edita la línea 2 de `status-badge.svelte` para agregar un tono:

   ```svelte
   export type StatusBadgeTone = "neutral" | "accent" | "success";
   ```

3. Revisa otra vez. El archivo editado ahora aparece como `modified`:

   ```sh
   cuilo status
   ```

   ```text
   clean     src/ui/atoms/status-badge/index.ts
   modified  src/ui/atoms/status-badge/status-badge.svelte
   ```

4. Pregunta de dónde viene una línea, con `path:line`:

   ```sh
   cuilo why src/ui/atoms/status-badge/status-badge.svelte:2
   cuilo why src/ui/atoms/status-badge/status-badge.svelte:13
   ```

   ```text
   src/ui/atoms/status-badge/status-badge.svelte:2 is yours: added or changed since generation; ui 0.2.0 piece `atom`
   src/ui/atoms/status-badge/status-badge.svelte:13 is from the pack (line 13 of the original); ui 0.2.0 piece `atom`
   ```

</Steps>

Este registro es lo que hace seguras las actualizaciones. Cuando el pack `ui` publica una versión nueva, `cuilo update ui` la fusiona con tu archivo editado en vez de sobrescribir tu línea. Consulta [Actualiza el código generado](/es-mx/guides/updates/).

## Mira el historial y deshaz

<Steps>

1. Lista las transacciones que puedes deshacer:

   ```sh
   cuilo log
   ```

   ```text
      1  add ui/atom  (2 file(s))
   ```

2. Deshaz la última:

   ```sh
   cuilo undo
   ```

   ```text
   error: these files changed after transaction 1; undo with force to discard the edits: src/ui/atoms/status-badge/status-badge.svelte
   ```

   cuilo se niega, porque deshacerla tiraría tu cambio en la línea 2.

3. Deja la línea 2 como estaba y vuelve a correr `cuilo undo`. O descarta el cambio con `--force`:

   ```sh
   cuilo undo --force
   ```

   ```text
   Undid transaction 1: add ui/atom
   ```

4. Revisa que no quede nada:

   ```sh
   cuilo status
   ```

   ```text
   Nothing generated yet.
   ```

</Steps>

La transacción creó `cuilo.lock`, así que al deshacerla también se borró el lockfile. De lo que agregó cuilo, solo queda `.cuilo/`.
